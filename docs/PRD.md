# 旅游站点产品需求文档（PRD）

版本：0.1

一、概述

目标：为国内外自由行用户提供一个轻量级、一站式的旅游产品发现与预订平台。用户可以浏览目的地、查看路线与行程详情、在线下单与支付，并获得个性化推荐与社交分享能力。

主要受众：

- 自由行旅客（18-45 岁），重视行程自定义与体验质量。
- 小规模旅行社/地接社，用于发布线路与管理订单。

二、产品定位与核心价值

- 覆盖短途周边游与中长途定制线路。
- 简洁的搜索与筛选体验，快速完成从发现到下单的流程。
- 强调移动端体验与社交分享，支持用户评价与照片展示。

三、MVP 范围（优先实现）

- 目的地与线路浏览：主页展示推荐目的地、列表与详情页。
- 搜索与筛选：按目的地、出发地、价格区间与出行天数筛选线路。
- 线路详情页：包含日程安排、费用说明、服务标准与图片画廊。
- 订单提交：填写联系人、出行人信息、选择出发日期与数量并提交订单。
- 支付接口（模拟）：支持模拟支付接口或接入第三方支付门户（扩展）。
- 用户账户：注册/登录、查看订单历史与提交评价。

四、功能需求（详细）

4.1 首页

- 推荐位（轮播）、目的地速览、热门路线。
- 搜索栏（关键字、日期、人数简易入口）。

  4.2 搜索与筛选

- 支持关键字搜索（目的地/线路名）。
- 筛选条件：出发地、目的地、价格区间、出行天数、出发日期范围、标签（亲子、探险、度假）。

  4.3 线路详情页

- 基本信息：线路名、评分、价格、出发/返回日期选择。
- 日程表：每日日程、包含/不含项目、图片与地图位置信息。
- 评价区：用户评分与文字/图片评价。

  4.4 订单与支付

- 订单页：联系人信息、出行人信息、发票信息（可选）。
- 支付：提供“模拟支付”流程（用于 MVP）并返回支付结果回调。

  4.5 用户系统

- 注册/登录（邮箱/手机 + 验证码或第三方登录扩展）。
- 个人中心：订单列表、订单详情、投诉/客服入口。

  4.6 推荐与个性化（基础）

- 基于浏览与订单的简单协同过滤：展示“你可能喜欢”的线路。

五、接口设计（高层）

- GET /api/destinations — 获取目的地列表
- GET /api/routes — 获取线路列表（支持筛选查询参数）
- GET /api/routes/:id — 获取线路详情
- POST /api/orders — 创建订单
- GET /api/orders/:id — 获取订单详情
- POST /api/auth/register — 用户注册
- POST /api/auth/login — 用户登录

响应统一约定：返回 JSON，包含 { code, message, data }。

六、非功能性需求

- 可用性：目标 99.5% 可用性（MVP 可放宽）。
- 性能：列表接口在常见分页下响应 < 500ms（取决于后端与 DB）。
- 安全：对用户敏感信息加密存储，所有接口走 HTTPS（部署阶段）。
- 扩展性：API 设计遵循 RESTful，可后续接入微服务或第三方支付。

七、验收标准（Acceptance Criteria）

- 用户可以在首页搜索并打开线路详情页。
- 用户能从线路详情页填写并提交订单（模拟支付成功）。
- 用户能注册/登录并在个人中心查看订单历史。

八、里程碑与估时（粗略）

- 第 1 周：需求确认，完成 PRD 与产品原型（页面流程图）。
- 第 2-3 周：完成前端 MVP（浏览、详情、下单模拟流程）。
- 第 4 周：后端基础 API、模拟支付接口与用户系统。

九、后续改进（非 MVP）

- 接入真实支付网关、第三方地图与行程优化推荐。
- 支持 KOL/达人内容与更丰富的社交功能。
